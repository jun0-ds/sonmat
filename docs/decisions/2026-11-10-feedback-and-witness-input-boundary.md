# 2026-11-10 — 피드백 활용과 witness 입력 격리

Updates: [훈수꾼과 witness의 역할 구분](2026-04-26-hunsugun-witness-seam.md), [승인된 실행 기준선](2026-09-11-approved-execution-baseline.md)

## Context

scribe는 witness의 지적이 다음 세션의 메인에게 전달되면 격리가 깨진다고 설명했다. 반면 autoloop은
메인이 그 지적을 보고 산출물을 수정하도록 했다. journal에만 판정을 남기라는 설명도 bridge에 짧은
판정 표시를 허용한 규칙과 어긋났다. 메인이 피드백을 활용하는 일과 새 witness에 과거 판정을 넣는 일을
구분해야 이 모순을 풀 수 있다.

류선생은 앞선 검토에서 witness 자체가 훈수꾼이라고 정정했고, 이번 작업에서는 파일별 수정안의 적용과
자연스러운 한국어 문장으로 다듬는 일을 요청했다. 이 결정은 승인된 수정안의 피드백·기록 경계를 정리한다.
새 시스템을 만들거나 전역 계약과 witness의 권한을 넓히지는 않는다.

## Decision

### 피드백과 새 비교

메인은 witness의 지적을 읽고 산출물을 수정하며 회고에서 교훈을 얻을 수 있다(MAY).
새 witness는 원 사용자 요청, 유효한 승인 기준선이 있을 때 그 기준선, 실제 산출물을 새로 비교해야 한다(MUST).
이전 판정, 메인의 해석과 학습 요약, worker의 보고, bridge와 journal 등 scribe가 남긴 기록을 새 witness의
입력이나 판정 근거로 전달해서는 안 된다(MUST NOT).

별도 컨텍스트나 Codex의 no-history 실행은 입력을 구성할 의무를 대신하지 않는다. 메인이 금지된 내용을
프롬프트에 직접 넣을 수 있기 때문이다. 실행 컨텍스트의 분리와 프롬프트 구성·인용 규칙의 준수를 구분한다.
기존 판정 종류와 승인 기준선의 권한은 유지한다.

### 기록과 교훈

자세한 지적 내용(finding)과 인용 근거는 journal에 남겨야 한다(MUST). bridge에는 짧은 판정 표시와 별도로 확인한
수정 결과, 승인된 결정, 미해결 상태를 적을 수 있다(MAY). 판정 근거를 요약해서 bridge로 옮기는 방식은
허용하지 않는다. 메인이 회고할 때 journal을 읽는 것은 허용되지만 기록된 판정 자체를 정답의 증거로 보지는 않는다.

witness의 지적을 일반 규칙으로 제안하려면 원천, 원 사용자 의도, 현재 상태를 다시 확인해야 한다(MUST).
scribe는 기존 가족 비교와 사용자 확인 절차에 따라 새 기록이나 기존 hint의 수정을 판단한다.
guard와 autoloop은 기존 hint가 있었는데도 발생한 실패를 이 경로로 넘긴다.
새로운 실패였다고 가정하거나 별도 규칙 체계를 추가하지 않는다.

### 실제 전달

scribe 스킬, Claude 에이전트 정의, Codex TOML에 같은 핵심 경계를 반영한다. witness 정의와 autoloop의
입력 구성 설명도 이에 맞춘다. TOML은 스킬에서 자동 생성되지 않으므로 스킬 수정만으로 설치된 에이전트에
전달됐다고 판단하지 않는다. 릴리스·설치·새 에이전트의 실제 로드는 각각 확인해야 하는 별도 단계다.

## Consequences

메인은 피드백을 활용하면서도 새 비교자에게 이전 판정을 전달하지 않을 수 있다. 문서의 정렬은 정적 대조로
확인하고, 실제 유용성은 원 요청과 당시 산출물, 직접 실행한 검사, 확인된 사용자 교정을 기준으로 판단한다.
journal은 사례를 찾는 색인이며 그 안의 자기 보고만으로 효과를 입증하지 않는다.

피드백을 메인에게서 숨기는 안은 수정과 학습 경로를 막으므로 채택하지 않았다. 과거 판정을 새 witness에
계속 넣는 안도 독립 비교의 근거를 오염시키므로 채택하지 않았다. witness와 훈수꾼을 별도 제품으로 다시
나누거나 새 관찰자·저장소·라우터를 도입하는 일은 이번 결정에 포함하지 않는다.

이 문서는 두 이전 ADR을 부분적으로 갱신하며 원문을 보존한다. 2026-11-10부터 위와 충돌하는 피드백 전달
금지 설명과 별도 제품 분리를 이번 작업의 근거로 되살리지 않는다. 그 밖의 유효한 승인·입력·권한 경계는 유지한다.
