# 스킬 발동 수동 점검

공식 가이드의 triggering test에 따라 각 요청에서 해당 스킬이 발동하는지 수동으로 점검한다. 각 요청을 독립된 대화에서 실행하고 발동 여부를 확인한다. punch는 제안 뒤 사용자가 수락할 때 실행하며, devil은 명시적으로 요청할 때 실행한다.

## autoloop

발동해야 한다:
- 여러 파일을 고쳐 이 기능을 끝까지 알아서 완성해 줘.
- 이 구현을 계획부터 평가까지 루프 돌려 줘.
- 마일스톤별로 구현하고 결과를 보고 다음 단계를 진행해 줘.
- 실패한 검사를 고치고 다시 검증하는 과정을 자율로 진행해 줘.
- 여러 단계로 이 리팩터링을 마무리할 때까지 반복해 줘.

발동하면 안 된다:
- 이 파일의 오타 하나만 고쳐 줘. (스킬 없음)
- 이 함수가 무슨 일을 하는지 설명해 줘. (스킬 없음)
- 이 주제의 자료만 조사해 줘. (스킬 없음)

## devil

발동해야 한다:
- 이 계획의 핵심 가정에 반론해 봐.
- 이 결정을 바꿀 만한 반례가 있을까? 검토해 줘.
- 대안 없이 선택한 이 해석을 devil로 따져 줘.
- 이 배포 계획이 괜찮은지 반대 관점에서 봐 줘.
- 이 비가역 결정의 가정을 비판하고 선택에 미칠 영향을 알려 줘.

발동하면 안 된다:
- 이 코드 변경의 부작용을 점검해 줘. (inspect)
- 결과물이 내가 요청한 의도에 맞는지 비교해 줘. (witness)
- 이 변수의 뜻을 설명해 줘. (스킬 없음)

## guard

발동해야 한다:
- 이 변경을 커밋해 줘.
- 민감할 수 있는 파일을 스테이징해 줘.
- 같은 테스트 실패가 반복되고 있어, 새 함정인지 확인해 줘.
- 커밋하기 전에 테스트와 민감 파일을 검사해 줘.
- 작업 중 규율을 어긴 부분이 있는지 점검해 줘.

발동하면 안 된다:
- 이번 작업의 인계 노트를 작성해 줘. (scribe)
- 산출물이 원래 요청과 일치하는지 판정해 줘. (witness)
- 이 계획의 가정에 반론해 줘. (devil)

## inspect

발동해야 한다:
- 다섯 파일을 바꾼 이 변경의 영향 반경을 확인해 줘.
- 세 곳에서 가져오는 공용 유틸을 고쳤으니 부작용을 점검해 줘.
- 이 인증 변경은 위험하니 의존성과 롤백을 다시 확인해 줘.
- DB 스키마 변경의 부작용을 살펴봐 줘.
- /inspect 이 동기화 스크립트 변경을 검토해 줘.

발동하면 안 된다:
- 삭제 후 빠진 것과 남은 잔재를 찾아 줘. (punch)
- 이 계획에 반론해 줘. (devil)
- 단어 하나의 뜻을 알려 줘. (스킬 없음)

## punch

발동해야 한다:
- 다 됐으니 빠뜨린 게 없는지 확인해 줘.
- 내보내기 전에 누락과 잔재를 점검해 줘.
- /punch 이 기능의 완결성을 확인해 줘.
- /punch residue 이름 변경 뒤 남은 참조를 찾아 줘.
- 구조를 삭제했으니 펀치 리스트를 돌려 줘.

발동하면 안 된다:
- 커밋 전에 테스트를 실행해 줘. (guard)
- 인증 변경의 부작용과 롤백을 확인해 줘. (inspect)
- 이 계획의 약한 가정을 찾아 반론해 줘. (devil)

## requery

발동해야 한다:
- 인덱스에서 못 찾았어. 지난번 결정을 어디 적어 뒀는지 다시 찾아 줘.
- grep에 안 나오는 인계 내용을 다른 표현으로 찾아 줘.
- 첫 검색에 없는데 그 기록의 이름이 바뀌었는지 찾아봐 줘.
- 이전 설정을 찾지 못했으니 시점을 바꿔 다시 검색해 줘.
- 추상적인 이름으로는 못 찾았어. 구체적인 표현으로 다시 찾아 줘.

발동하면 안 된다:
- 첫 검색에서 찾은 파일을 열어 줘. (스킬 없음)
- 최신 소식을 웹에서 검색해 줘. (스킬 없음)
- 이번 작업의 결과를 기록해 줘. (scribe)

## scribe

발동해야 한다:
- 세션을 마무리하고 다음 세션에 인계해 줘.
- 작업 결과와 남은 상태를 bridge note에 적어 줘.
- 완료한 마일스톤과 검증 결과를 기록해 줘.
- 같은 사용자 교정이 두 번 나왔으니 프로젝트 규칙 기록을 검토해 줘.
- guard가 감지한 새 함정을 기록할지 검토해 줘.

발동하면 안 된다:
- 못 찾은 이전 기록을 다시 찾아 줘. (requery)
- 커밋 전 민감 파일과 테스트를 검사해 줘. (guard)
- 이번 산출물이 사용자 의도에 맞는지 독립적으로 비교해 줘. (witness)
